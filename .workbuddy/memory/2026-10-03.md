### 关键手法：覆盖 Tailwind 自带色名（省掉全站改类名）
在 `src/index.css` 的 `@theme` 里直接重定义 `--color-slate-50..950`：
冷灰蓝 → 带土黄的暖灰（纸/墨）；`brand` 靛蓝 → 朱红 `#ad4324`；
emerald/amber/red 降饱和（苔绿/赭石/深朱）。
**全站不用改一行类名即整体换肤**，换品牌色只改这一块。
⚠️ 这是"改写框架默认语义"的取舍：务必在文件里写明原因（已写），否则后来者会困惑。

### 这一路踩的五个坑（都非显而易见，务必记住）

1. **自动续码是反人类的** —— 我每 12 分钟换新设备码，用户却可能输入聊天里**更早出现**的旧码，
   于是"授权成功但没人取票"（脚本已换成新码在等）。正确做法：一次性单码，并强调"只认这一个"。
2. **令牌必须第一时间落盘** —— 第一版拿到 TOKEN 后没写文件，进程一退就丢，白白再授权一次。
   现存在 `$env:TEMP\cet4_gh_token.txt`（`cet4_auth3.ps1` 会优先复用已存令牌）。
3. **PowerShell 5.1 把无 BOM 的 UTF-8 当 GBK 读** —— 中文注释里某些汉字会吞掉紧跟的换行符，
   整个脚本静默语法错误（`Try 语句缺少 catch`）。自动化 .ps1 **一律纯 ASCII**。
   校验方法：`[System.Management.Automation.PSParser]::Tokenize(...)`
4. **本机有本地代理 `http_proxy=http://127.0.0.1:58916`** —— 对 github.com 的 CONNECT 回 502。
   .NET（Invoke-RestMethod）不走这个变量所以 API 能通，**git（libcurl）会走所以 push 挂**。
   推送前需清空 `HTTP_PROXY/HTTPS_PROXY/http_proxy/https_proxy`。
5. **★ 最大的坑：系统 gitconfig 里 `credential.helper=manager`（Git Credential Manager）**
   在非交互环境里**静默崩溃** → `git push` 一律 exit 128 且**零输出**，极易误判成网络问题。
   ✅ 可用命令（令牌写进 URL + 禁用管理器）：
   ```
   git -c credential.helper= push -u origin main
   # origin = https://1317780759:<TOKEN>@github.com/1317780759/cet4-master.git
   ```
   （`gh auth setup-git` 写入的 `!gh.exe auth git-credential` 在本机同样不可用，依赖 shell 派生）

### 排查手法
输出捕获用 `*>&1 | Out-File`（PowerShell 对 native stderr 经常丢），
配合 `GIT_CURL_VERBOSE=1` 才看到 GitHub 返回 `www-authenticate: Basic`（= 凭据根本没送出去）。
